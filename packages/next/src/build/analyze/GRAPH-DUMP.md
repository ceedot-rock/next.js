# Analyzer graph dump (v1)

`next analyze --output=json` analyzes a production build and streams one JSON object per line to stdout. For an existing snapshot from either `next analyze --output` or `next build --analyze`, use `next analyze --output=json --snapshot <id>`; list IDs in `.next/diagnostics/analyze/history/history.json`. Add `--route /route-key` to restrict route-local records while retaining the whole-app `module` graph. Plain `next build --analyze`, `next analyze`, and bare `next analyze --output` retain their existing UI/disk behavior. Only an explicit JSON invocation emits NDJSON. No NDJSON is stored unless the caller redirects stdout.

The first record is `{"type":"meta","schema_version":1,"snapshot_id":"...","module_index_hash":null|string,"route_count":number,"selected_routes":number}`. Each subsequent line is exactly one independent JSON object. Snapshot IDs and `route_index` distinguish historical builds and repeated route keys. These are snapshot-scoped, not stable cross-build identifiers; the history writer can replace an ID when two captures finish within one second, so retain separate dumps when comparing builds. Future incompatible changes require a new `schema_version`; fail on unknown versions. A command that fails or returns an incomplete stream must be discarded even if some records were written.

- `module`: `ident` (exact whole-app identity, preserving variants), `path`, and `dependencies` with `sync`, `async`, and `traced` arrays of imported **identity strings**. Edges point importer → imported; traced edges are not browser imports.
- `route`: `route` key, `route_index`, and optional `entries`/`coverage` as available. `null`/`unknown` means there is no evidence, **not** an empty root set.
- `output`: route identity, emitted `filename`, `modules` (`null` when there is no exact join), `coverage` (`exact`, `unsupported`, `not_a_chunk`, or `unknown`), and possibly `unresolved_references`. Do not treat an output as entirely covered unless coverage is `exact` and unresolved evidence is clear.
- `part`: route identity, output `filename`, `source_path`, uncompressed `size`, and `compressed_size`. These numbers are attribution weights, not predicted savings.
- Later v1 producer layers may add `group`, `load_edge`, `unjoined`, and `unresolved` records for explicit client/bootstrap/async/worker provenance. Their absence in an earlier v1 snapshot means **unknown**, not false. Groups can overlap and be cumulative, and generic asset references do not guarantee a browser request.

Records and their identity lists have deterministic order for the **same snapshot**. Neither numeric `route_index` nor output filenames nor module identity strings are promised to be identical across builds. The exporter privately validates the versioned binary UI artifact, source tree and edges and cross-file fingerprint when indexed joins exist; agents should never parse that private binary format themselves. Unversioned snapshots must be regenerated. For large apps, redirect stdout to a temporary file and filter the NDJSON; don't paste the complete graph into a model prompt.
